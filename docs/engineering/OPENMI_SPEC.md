# OpenMI Specification (TSM Profile)

## Standing position: do NOT adopt OpenMI as a coupling runtime

OGC 11-014r3 (OpenMI 2.0) is a dormant runtime-coupling standard (~2010)
with no maintained Python implementation (Java/C# only). TSM does not adopt
it. The pasted material describes OpenMI as if it were a new build; in
fact TSM already has a transport profile, and this document describes that
profile plus a minimal explicit-exchange extension. If true multi-physics
model coupling is ever needed, evaluate CSDMS BMI (real Python support)
instead.

## Existing canonical profile (do not duplicate)

- Proto: `tsm-console/proto/openmi.proto` (`tsm.openmi.v1`)
- Runtime contract: `backend/openmi_contract.py`
- gRPC service: `backend/openmi_service.py` (streaming Exchange,
  RegisterComponent, Health; resilient validation, backpressure shedding)
- Tests: `backend/test_openmi_service.py`

The service is a transport boundary. It does not manufacture engineering
values and does not imply any external solver executable is installed.

## Exchange object (extension)

`backend/openmi_exchange.py` adds the explicit per-exchange metadata the
pasted material calls for:

```ts
{
  quantity,       // e.g. "Discharge"
  unit,           // e.g. "cfs"
  crs,            // e.g. "EPSG:2966"
  verticalDatum,  // e.g. "NAVD88"
  timestep,       // ISO-8601 timestamp of the exchange step
  value
}
```

Every field is required. The resilient wrapper `try_exchange` returns
`{"status": "UNAVAILABLE", ...}` on missing metadata or invalid values —
it never raises into the caller as a block, and never interpolates.

## Supported exchanges

Flow, stage, velocity, rainfall, recharge, sediment — as labeled
quantities only. A quantity is never relabeled into a different physical
meaning by the bridge.

## What is rejected

- Exchanges with missing unit, CRS, datum, or timestep → `UNAVAILABLE`.
- Non-finite values → `UNAVAILABLE`.
- Synthesized gauge values: the rejected `firecrawl_openmi_coupler.py`
  pattern (sine-wave gauge data) must never enter an exchange or an
  evidence path. Values are passed through, never generated by the bridge.

## Downstream gate

The Archimedes screening engine (`backend/governance/archimedes_engine.py`)
reads coupled output and screens it against state administrative codes
without altering raw physics fields. It is advisory (S1) and read-only:
screening evidence, never a regulatory determination.
