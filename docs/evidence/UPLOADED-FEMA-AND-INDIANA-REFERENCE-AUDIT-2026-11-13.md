## Concrete TSM integration boundaries

1. **Source acquisition / terrain.** Separate published Indiana GIO bare-earth DEM/DTM tiles from render-only hillshade/aspect and from building roof LiDAR. Register actual imagery [ImageServer](https://di-ingov.img.arcgis.com/arcgis/rest/services/DynamicWebMercator/Indiana_2016_2020_DEM/ImageServer) and [official 2016–2020 tile-footprint FeatureServer/0](https://gisdata.in.gov/server/rest/services/Hosted/Indiana_DEM_Tile_Footprints/FeatureServer/0) as distinct service records. ImageServer `EPSG:3857` display coordinates do not establish a vertical datum; source metadata, verified raster bytes/CRS, nodata, acquisition year, native sampling and GEOID lineage are still required.
2. **Survey/geodesy.** Do not label LiDAR-derived roof heights as a certified FFE, LAG, or engineering survey. Record source horizontal CRS (for western 2020 LiDAR, NAD83(HARN) Indiana West / EPSG:2968, as documented by [NOAA InPort 69202](https://www.fisheries.noaa.gov/inport/item/69202)), source NAVD88/GEOID12B vertical frame, and target EPSG:2966 separately; document transformations explicitly. SIDs 41/42/118 require special attention for formal mapping projects.
3. **Hydrology/hydraulics.** TSM should treat GIS prep, read-only HEC-RAS adapters and cinematic views as *supporting tools*, not independently approved hydraulic models. Store exact HEC-RAS model/version/run, input and output digests, hydrographs, controlling study and agency acceptance. A current accepted model and independent engineering/agency review are required before a **regulatory** claim. The newer FEMA 2023 Model Acceptance Guidance is a **web-derived update**, separate from the uploaded 2020 text.
4. **QA report rules.** A cHECk-RAS-inspired checklist is useful for *steady* river model metadata and reviewer prompts. Mark **not applicable** for unsteady/2D instead of giving them a passing legacy cHECk-RAS badge. Distinguish floodway surcharge, cross-section consistency and actual upstream/downstream tie-in requirements from simplistic fixed defaults.
5. **Ecology.** Only use the 2000 Mississippi programmatic opinion as an example of a Tier I/Tier II evidence hierarchy. Add a local project-specific USFWS consultation placeholder for changes affecting waterways; do **not** infer that listed species actually occur at the proposed site.
6. **Community and cinematic runtime.** Optional public dashboard sections may display independently sourced energy, water, employment, and mitigation indicators with explicit “unknown” status. For native UE5.8 offline rendering, emulate **temporal low-resolution first/high-resolution on-demand** as a design pattern; never install NW.js to implement it.

## Proposed technical QA receipt contract

A regulatory evidence receipt must distinguish source and model acceptance, source format and precision, reference frames, certified survey status, local NFHL/FIRM authority, and reviewer decision. Missing evidence is a *blocked regulatory publication claim*, not a reason to hide raw public data. A prerelease advisory visualization can remain accessible with prominent uncertainty labels.

No uploaded PDF grants permission to call the 2016–2020 DEM itself a roof DSM, infer the missing **2,566** Posey building heights, certify 23,082 3D buildings, replace actual HEC-RAS 2D model calibration, or mark the Windows 11 offline Shipping release as verified.
