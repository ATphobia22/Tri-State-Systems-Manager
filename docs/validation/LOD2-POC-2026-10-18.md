# LOD2 Roof Mesh Generation — Proof of Concept (2026-10-18)

## Objective

Validate the TU Delft 3DBAG/geoflow plane-arrangement approach for generating
LOD2 roof meshes from LiDAR-derived roof planes, using pure Python
(shapely + numpy + trimesh). This is a **proof of concept**, not production code.

## Input Data

- `/home/hatch/workspace/pipeline-run/posey-buildings-lod2-23082.geojson`
  (23,082 features; 7,453 with `roofPlanes`)
- Footprints in EPSG:4326; roof planes in the LiDAR EPT native CRS,
  **empirically identified as EPSG:3857** (Web Mercator, metres) by testing
  which CRS makes plane heights match `lidarRoofElevM`
  (median error 2.4 m over 200 buildings; EPSG:26916 and EPSG:2968 give
  errors of 10^5–10^6 m).

## Method (as implemented)

Per building (`scripts/geospatial/lod2-proof-of-concept.py`):

1. Transform footprint EPSG:4326 → EPSG:3857; subtract centroid as local origin
   (float32 precision for GLB).
2. **Line extraction:** pairwise plane-intersection lines (3D → projected to 2D).
   Near-parallel pairs (dihedral < 5°) skipped. *Deviation from 3DBAG: boundary
   lines from α-shapes are omitted — no inlier points are available in the input.*
3. **Line regularisation:** angle clustering (mod 180°, 5° tol) + perpendicular
   distance clustering (0.5 m tol); longest line kept per cluster.
4. **Subdivision:** clip lines to footprint, node + `shapely.ops.polygonize`,
   keep cells ≥ 0.5 m² inside footprint.
5. **Plane assignment:** highest plane at cell centroid.
6. **Triangulation:** shapely Delaunay + containment filter, with area-coverage
   check (≥98%) and centroid-fan fallback.
7. **Roof:** lift triangle vertices onto assigned planes (CCW-up winding).
8. **Walls:** built from the roof mesh's directed boundary edges (preserving
   triangle winding direction — critical: unordered edges flip half the walls
   inward, causing volume cancellation). Outer edges → walls to floor.
9. **Floor:** fan from footprint centroid at `lidarGroundElevM` (downward winding).
10. **Repair:** merge vertices (2 cm tol), fill holes, then deterministic
    orientation flip if signed volume < 0 (a watertight mesh with positive
    volume has outward normals by the divergence theorem).
11. Export GLB with `tsm_origin_3857` and `tsm_objectid` metadata.

## Bugs Found and Fixed During PoC

1. **Unordered boundary edges** flipped half the walls inward → volume
   cancellation (volumes 67–2,161 m³ instead of ~10,000–35,000 m³).
   Fixed by preserving directed edges from source triangles.
2. **`trimesh.is_volume` tautology:** `is_volume` is False when volume ≤ 0,
   so `if is_volume and volume < 0` never fires. Changed to test
   `is_watertight` instead.
3. **Flip-before-fill ordering:** orientation check must run after
   `fill_holes()`, since a mesh with boundary edges has no defined volume.
4. **Heuristic `fix_normals`/`fix_inversion` removed:** they propagated wrong
   majority orientations. Replaced with deterministic volume-sign flip.

## Limitations (Why This Is Not Production)

- **No α-shape boundary lines:** without inlier points, plane support regions
  can't be recovered; intersection lines alone suffice for simple roofs but
  complex roofs need the full 3DBAG boundary extraction.
- **Highest-plane-at-centroid** is a crude labelling; 3DBAG uses graph-cut
  optimisation balancing data fit vs. complexity.
- **No eave overhang handling**, no dormer/chimney detail, no texture/UVs.
- **Single-floor elevation** per building; adjacent-building z-fighting not addressed.
- **Not validated** with val3dity (ISO 19107) or against LiDAR point-to-mesh RMSE.
- Only tested on 30 of 7,453 buildings with planes.
