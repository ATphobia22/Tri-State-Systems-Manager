# Ohio–Wabash offline workstation map

From this directory, run the following with Bash, Osmium, Docker Compose, and the console's locked npm dependencies installed. This optional browser workstation runs independently of Windows Shipping.

1. Stage the Indiana, Illinois and Kentucky Geofabrik extracts from one replication timestamp. Keep the dated download URLs alongside the input checksums. Run `bash prepare.sh indiana.osm.pbf illinois.osm.pbf kentucky.osm.pbf data`. It builds a single driving graph across state boundaries using the repository's MLD image.
2. Place a Protomaps vector archive in `data/tristate-valley.pmtiles` and a lossless Mapbox Terrain-RGB archive (256-pixel tiles, metre elevations) in `data/tristate-terrain.pmtiles`. Clip to west −88.6, south 37.4, east −87.0, north 38.6. The east boundary excludes downtown Owensboro. Record the actual bounds, source dates, licenses, hashes, terrain units and vertical datum with the snapshot. For terrain start with the existing 3DEP build pipeline and convert the resulting MBTiles using `pmtiles convert source.mbtiles data/tristate-terrain.pmtiles`. Preserve nodata in the upstream raster.
3. Supply redistributable local fonts and SVG icons in `data/fonts` and `data/icons`. Install MapLibre via the existing tsm-console lockfile. Set NOMINATIM_PASSWORD to a random alphanumeric value and run `docker compose pull` during connected preparation. Record the resolved image digests before transferring the snapshot.
4. Run `docker compose up -d --pull never`. Open http://127.0.0.1:8090 after Nominatim finishes its initial import. Its database volume belongs to this snapshot. Use a fresh Compose project name and volume for each replacement snapshot and stop the previous project before switching.
5. With the external network disconnected, check the water, roads and relief around Mount Vernon. Search an address and a full Plus Code, select two points on opposite banks joined by a road crossing, then request a route. Short codes resolve relative to the current map center.

Search results come from OSM via Nominatim. County E-911 records need source identifiers, release dates, documented reuse terms and unit-aware matching before publication. A nearby point with the same house number and street can represent a distinct unit. Routing, search and terrain visualization are reference layers. Display the source attribution with any redistributed snapshot.

Sources: [Geofabrik](https://download.geofabrik.de/north-america/us.html), [OSM attribution](https://www.openstreetmap.org/copyright), [Protomaps](https://docs.protomaps.com/), [OSRM](https://github.com/Project-OSRM/osrm-backend), [Nominatim container](https://github.com/mediagis/nominatim-docker), [Plus Codes](https://github.com/google/open-location-code).

For an independently sourced public address layer, normalize the source to RFC 7946 Point features with the original feature ID and a complete `properties.display_name` including unit and locality. Run `python address_index.py input.geojson addresses.sqlite --agency "source agency" --release "release identifier"`. The SQLite file supports exact normalized-key lookup and preserves overlapping addresses and the source digest. This staging index is independent of Nominatim's OSM database.
